Там, где Telegram не открывается, покупать VPN через бота нельзя: чтобы купить VPN, уже нужен VPN. Магазин на адресе подписки принимает оплату в обычном браузере. Telegram для этого не нужен.

Покупка идёт тем же путём, что и в боте: платёж появляется в разделе **Платежи**, вебхук `subscription.paid` уходит после зачисления, а повторное уведомление платёжной системы не выдаёт подписку второй раз. Переход браузера обратно на сайт сам по себе ничего не зачисляет — панель перечитывает счёт у платёжной системы и сверяет сумму и валюту.

## Включить

<Steps>

1. **Настройки → Подписка → Покупка в браузере.** Переключатель выключен, пока вы его не включите. Продажа подписок включается отдельно: без неё магазину нечего выставлять.

2. Почта для кода входа: сервер SMTP, порт, адрес отправителя и шифрование. Пароль обратно не показывается. Без почты новый покупатель войти не сможет, а уже купленную подписку можно продлить по её ссылке.

3. Адрес после оплаты — куда платёжная система вернёт браузер. Пусто: страница магазина. Это не адрес, который присылает браузер покупателя.

4. Если свой сайт вызывает API магазина, перечислите его origin (например `https://example.com`), по одному в строке. С того же адреса, где открыт магазин, список не нужен.

</Steps>

Адрес магазина — адрес подписки плюс `shop`. На странице подписки появляется кнопка «Продлить в браузере»: она привязывает эту подписку к сессии и открывает магазин.

## Как покупают

Новый покупатель указывает почту и вводит код из письма (или открывает ссылку из письма). Сессия — cookie `HttpOnly`, её нельзя прочитать из скрипта страницы. Дальше он выбирает тариф, срок, пакет устройств и платит.

## Чем платят

В той же карточке три способа. Все три видны и в боте.

- **Platega.** MerchantId и секрет из кабинета platega.io, способ оплаты из их документации (по умолчанию СБП). Адрес колбэка, который показывает панель, вписывается в кабинет Platega. Колбэк несёт те же MerchantId и секрет; панель всё равно перечитывает счёт и зачисляет его, только если статус CONFIRMED, валюта RUB, а сумма не меньше счёта. Уже установленное дополнение Platega продолжает принимать оплату, пока эта карточка выключена.
- **RollyPay.** API-ключ и секрет подписи кассы. ID терминала необязателен, если платите ключом. Адрес колбэка вписывается в кассу как `callback_url`. Подпись — HMAC-SHA256 от `время.тело` секретом кассы. Оплаченным счёт становится после ответа `paid` на запрос статуса, с той же проверкой суммы и валюты.
- **CryptoBot.** Это уже существующее дополнение маркетплейса `cryptobot`, панель его не дублирует. Установите дополнение и введите API-токен Crypto Pay из @CryptoBot.

Секреты в браузер не попадают: пустое поле при сохранении оставляет прежний. У Platega и RollyPay в опубликованном API нет возврата, поэтому промокод на них не принимается — запоздавший платёж со скидкой нельзя было бы вернуть. На CryptoBot промокод работает, если дополнение сообщает, что умеет возвращать.

Продление не требует почты: достаточно ссылки подписки. Она и есть секрет, как и для самой страницы подписки.

Вход через Telegram — дополнительно, если бот подключён. Виджет просит у BotFather домен магазина (`/setdomain`). Токен бота в браузер не попадает: панель проверяет подпись у себя. Stars в магазине нет — ими платят только внутри Telegram. Баланс доступен только тому, кто вошёл через Telegram: это баланс телеграм-аккаунта.

Реферальная программа и партнёрские начисления считаются у покупок с телеграм-аккаунтом. Покупка по почте или по ссылке подписки в них не входит: у неё нет телеграм-аккаунта, к которому их привязывать.

## API для своего сайта

Те же методы, что у страницы магазина, под `…/shop/api/`:

| Метод | Путь | Что делает |
| --- | --- | --- |
| GET | `/shop/api/config` | Включён ли вход по почте и имя бота для виджета |
| POST | `/shop/api/code` | Письмо с кодом |
| POST | `/shop/api/login` | Вход по коду, ставит сессию |
| POST | `/shop/api/telegram` | Вход виджетом Telegram |
| POST | `/shop/api/token` | Продление по ссылке подписки |
| GET | `/shop/api/offers` | Тарифы, сроки, пакеты устройств, способы оплаты |
| POST | `/shop/api/promo` | Проверка промокода, без списания |
| POST | `/shop/api/pay` | Счёт. В ответе адрес оплаты |
| GET | `/shop/api/order?order=` | Статус счёта. Не зачисляет |

Изменяющие запросы несут заголовок `X-Mikan-Shop: 1`. С чужого сайта браузер его не поставит формой, а origin должен быть в списке: иначе ответ без CORS и запрос отклоняется. Для такого сайта вход возвращает токен сессии (`Authorization: Bearer`), потому что cookie чужого сайта браузер на запрос не приложит. Секретов панели в ответе нет.
