The **Diagnostics** page in the panel's menu gathers what you used to need SSH for. Pick a server: the panel's server or any node.

## Logs

The last 2000 lines of the panel's log and of each node's. Tokens, keys, passwords, subscription links and secret paths are cut out before a line reaches the log. There is a level filter (all, warnings, errors), a text search, a refresh every 5 seconds and copying of the lines shown.

## Check

**Run the check** runs `mikan doctor` on the server itself, not in a container: Docker and the containers, ports, ufw rules, port 80, the clock, DNS, access to GitHub and GHCR, disk and memory, and on a panel's server also its own address — the port from the database against the listener, and the domain against this server's addresses. Every line has a hint on what to do. Waiting for the report takes up to a minute.

**Restart** restarts the containers of the panel's server or of a node. The panel or the node is unreachable for a couple of seconds.

How it works: the panel writes a request file into its data directory and a systemd unit on the server runs the command and returns the result. For a node the request goes over the node API. A server installed before 0.5.2.0 needs one `mikan update` for this; until then the check answers "the server did not answer".

## Reachability

Checks whether the server opens for users in Russia. Handy before you buy a server or install mikan on it: type an IP or a domain and up to three TCP ports. Port 22 is open on almost any server with SSH, start with it.

The [Globalping](https://globalping.io) service does the check: its points in home and mobile internet in Russia (where the blocks are) and in Russian data centres connect to the ports three times each. To compare, points in Germany, the Netherlands and Finland do the same. The result in one line:

- **opens from Russia**: it opens from everywhere;
- **does not open for everyone**: some operators block it;
- **blocked in Russia**: it opens from Europe, not from Russia. Another IP or another host is needed;
- **answers from nowhere**: the port is closed, the host's firewall drops it, or the server is off.

"1 of 3 got through" is a sign of a block too: an open port lets every try through.

:::caution[What this check does not see]
The server's address goes to Globalping. The check sees a block of the IP and the port, not a block by protocol and not the whitelists of mobile operators. Without a key Globalping gives about 250 checks an hour from one address; the result is kept for 2 minutes, and one check runs at a time.
:::

## Geo bases

:::note[New in 0.5.2.0]
The geo base check is new in 0.5.2.0.
:::

Sites and apps tell a client's country by geo bases, and the bases often disagree. If one base puts your server's IP in another country, a service shows the wrong region or refuses. The **Geo bases** tab shows what the bases think of an address.

Enter the server's IP or domain (the hint offers your nodes' addresses) and press "Check the geo bases". The panel asks ten public bases (MaxMind, ipinfo.io, IP2Location and others), which takes up to ten seconds. The result in one line: "All N bases put the address in: country" or "The bases disagree: country by N of M". Below, each base with its answer, the ones that disagree are marked. A base that did not answer is marked too: did not answer in time, a request limit or no answer. The result of a recent check is shown from the cache.

:::caution[What this check does not see]
The server's address goes to public geo bases. How services such as YouTube or Netflix see the IP is not shown: they have bases of their own.
:::

For nodes the same check is in the "Check node" window, see [Nodes](/arikan/en/nodes/nodes/#country-in-the-geo-bases).

## Terminal

The tab appears for an operator with "Terminal" level access and only for the servers you ticked for it. Details and limits are in [Support access](/arikan/en/operations/support-access/#terminal).

## When the panel does not open

Then the page is out of reach. Run `mikan doctor` on the server: the same report in the terminal. For a support ticket there is `mikan support <code>`, see [The mikan command](/arikan/en/operations/cli/).

## The server answers but the internet through it does not

The classic picture: ping to the server goes through, the panel sees the node, and nothing opens for the clients. It is always one of four places — the node's card names the first two at once.

1. **The node has no way to the internet.** Look at the card's **"Internet from the node"** line: every half minute the node itself connects to a public address by TCP and asks its resolver for a public name. "no" (with a banner naming the reason) means the server is reachable while its uplink or DNS is down: that is the host's and the server's network, not the panel or the clients. On the server check `curl -sS -o /dev/null -w '%{http_code}\n' https://1.1.1.1` and `getent hosts www.google.com`; both failing — call the host, only the second — fix DNS (`/etc/resolv.conf`, `nft list ruleset`).
2. **The node's process restarts.** The **"Up for"** line is the process's uptime: a small one after the outage means a restart on our side — see `arikan status` and the node's `docker logs`; a continuous one means the process never died, keep looking.
3. **Name resolution is broken on the client.** Sites open by IP and not by name: the device's DNS. In Clash apps these are the [DNS on the device and DNS at the exit](/arikan/en/subscriptions/routing/#dns) cards on the routing page; Xray apps (Happ, v2RayTun) resolve through the node — turn on "Read the site on the server" and check the resolver at the exit.
4. **DPI throttles the data.** The node is alive, "Internet from the node" is yes, the port opens (the "Check node" window — a check from Russia), but the clients' connection stalls or crawls. The sign is tiny packets and almost no speed while ICMP ping flows. That is a block of one protocol or address on the path: change the inbound's protocol (Vision, XHTTP), send clients through a cascade to another node (Nodes → the card → Exit), check from another operator and compare `mtr` to the server. In Russia REALITY without Vision and plain VLESS are throttled first; XHTTP and Vision hold longer.

If the inbounds' ports moved recently (autotune or a manual edit), a client may sit on the old port until its subscription refreshes: refresh it in the app. For a support ticket attach the card's uptime and "Internet from the node" line, `mikan doctor` and the node's log tail (the "Log" page in the panel).
