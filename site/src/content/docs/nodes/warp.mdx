У каждой ноды может быть свой Cloudflare WARP. Через него выходят выбранные протоколы, домены и сети, остальное идёт напрямую. Это помогает, когда сайты не любят адрес вашего хостера.

## Подключить

Кнопка **WARP** на карточке ноды, два способа:

- **Зарегистрировать**: панель сама создаёт бесплатный аккаунт Cloudflare, как приложение WARP или wgcf. Можно добавить «Ключ WARP+» из приложения 1.1.1.1 (Аккаунт → Ключ).
- **Свой конфиг**: вставьте конфиг WireGuard из wgcf, warp-plus или экспорта приложения. Нужны `PrivateKey`, `Address` и `PublicKey` пира. Если в конфиге нет строки `Reserved`, панель предупредит: при регистрации через панель она заполняется сама.

## Что пускать через WARP

- **Протокол целиком**: в настройках подключения **Выход в интернет → WARP**.
- **Домены и сети** для всех протоколов ноды: поле «Домены и сети через WARP», по одному на строку. `example.com` включает поддомены, `104.16.0.0/13` задаёт сеть. До 1000 строк.

Переключатель «WARP включён» на время пускает всё напрямую, аккаунт и списки при этом сохраняются. Выключить WARP или удалить его можно, только когда через него никто не выходит: протоколы с выходом **WARP**, а если нода выпускает трафик других нод — маршрут каскада **WARP**. Иначе трафик ушёл бы с адреса сервера, и панель откажет с этим объяснением.

:::caution
Если WARP не работает, его трафик не уходит напрямую с адреса сервера. Протокол с выходом через WARP молчит, пока WARP не вернётся. То же для каскада: трафик других нод через эту ноду не выйдет, а не уйдёт с её адреса (см. [Каскад через WARP](/arikan/nodes/cascades/#каскад-через-warp)).
:::

## Проверка

Окно WARP показывает состояние: выключен, не проверен, работает или не работает. Когда работает, видно, какой адрес видят сайты и через какой дата-центр Cloudflare идёт трафик. Кнопка **Проверить** проверяет заново.

Если проверка не проходит, панель пишет причину. Та же причина попадает в лог ноды и в уведомление в Telegram.

| Причина | Что значит |
|---|---|
| нет ответа по UDP | точка входа Cloudflare не ответила. Хостеры часто режут UDP: попробуйте другую точку входа в своём конфиге |
| нет ответа по HTTPS | туннель поднялся, но cloudflare.com не ответил вовремя |
| DNS | имя не разрешилось через WARP |
| TLS | ошибка TLS по пути |
| соединение отклонено | мешает файрвол или правила исходящих соединений |
| ещё не загружен | нода ещё не применила WARP, подождите минуту после сохранения |
| нода недоступна | панель не достучалась до ноды или нода старой версии |

По умолчанию нода ходит к точке входа `162.159.192.1:2408`.
