---
title: Обратный туннель
description: Нода сама подключается к панели и отдаёт по этому соединению свой API — когда панель не может достучаться до ноды.
---

Обычно панель сама подключается к ноде на её API-порт. Бывает, что это направление не работает, а обратное — работает: панель в одной стране, нода в другой, и пакеты панели до ноды не доходят («Порт N не отвечает: пакеты теряются по дороге»).

Тогда нода подключается к панели сама и отдаёт свой API по этому соединению. На карточке ноды видно: **через обратный туннель, нода подключилась N назад**.

## Как это устроено

- Нода открывает HTTPS-соединение на адрес панели из ключа подключения, на её собственный порт: `GET /node/tunnel`. Отдельного порта и правила файрвола не нужно.
- Нода предъявляет свой сертификат — тот, чей отпечаток панель уже хранит для неё. Панель принимает соединение, только если отпечаток совпал: чужой сертификат, сертификат удалённой ноды или перевыпущенного ключа получает отказ (и панель пишет это в лог без адресов и ключей).
- Внутри соединения — мультиплексор (yamux): панель открывает поток на каждый свой запрос, нода отвечает обычным API. Поток начинает панель, нода открыть поток не может.
- API внутри потока идёт по TLS с теми же пинами, что и на прямом соединении: панель проверяет сертификат ноды, нода — сертификат панели. Туннель ничего не читает из этого трафика.
- Одно соединение на ноду: новое вытесняет старое (нода переподключилась, на её сервере запустился второй процесс). Об этом есть строка в логе панели.
- Обрыв: нода переподключается с растущей паузой (от 2 секунд до 5 минут) и случайной добавкой, чтобы после возврата панели ноды не стучались все сразу. Пока туннеля нет, панель пробует прямой путь.

## Нода без открытого API-порта

Новым нодам панель по умолчанию **не разрешает слушать API-порт**: единственный путь к ним — обратный туннель. Это убирает открытый порт с сервера ноды совсем и снимает надобность в правиле «API ноды только с IP панели».

Переключатель — в настройках ноды, **Слушать API на своём порту**. Он же возвращает порт старой ноде: у нод, добавленных до появления туннеля, порт остаётся открытым, как был.

:::caution
Выключенный порт означает: если обратный туннель не поднимется, нода станет недоступна. Вернуть порт можно на сервере ноды:

```
MIKAN_NODE_INBOUND_API=on
```

в её окружении (или `MIKAN_NODE_API_LISTEN=off` → `on`), затем перезапустить ноду. Нода запоминает ответ панели и после перезапуска не открывает порт сама, пока панель не скажет.
:::

## Что нужно, чтобы туннель поднялся

- **Панель отвечает по HTTPS на своём адресе.** Нода проверяет сертификат панели как обычный клиент: если панель стоит на голом IP, а сертификат выписан на домен, проверка не пройдёт. Так же ведёт себя и hello ноды при установке.
- **В ключе подключения есть адрес панели.** Ключи, выданные панелью до появления hello, адреса не несут: нода подключается только к панели, перевыпустите ключ.
- **Сертификат ноды — тот, что знает панель.** Перевыпуск ключа или удаление ноды рвёт туннель: новая нода подключится с новым сертификатом, удалённая получит отказ.

## Если не работает

- На карточке: «Обратного туннеля нет» — нода не подключалась. Проверьте на сервере ноды её лог: `reverse tunnel: the panel does not take it` с причиной.
- `403` в логе ноды — панель не узнала сертификат: ключ перевыпущен, нода удалена или это не её сертификат.
- `x509` в логе ноды — панель ответила сертификатом, который нода не может проверить (адрес — IP, сертификат — на домен; или сертификат панели самоподписанный).
- Туннель поднят, а запросы не идут — смотрите лог панели: `node tunnel: the tunnel is over` говорит, почему закрылось соединение.
