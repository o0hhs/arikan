## Бэкап на сервере

```bash
arikan backup
```

Архив `mikan-ГГГГММДД-ЧЧММСС.tar.gz` появится в `/opt/mikan/backups`. В нём `config.json` и `secrets/` (на сервере, поставленном до 0.5.2.0, `.env`), `compose.yaml`, согласованный снимок базы, сертификаты панели, данные ноды и настройки адаптеров оплаты. Внутри все секреты сервера, поэтому папка доступна только root.

Перед опасными операциями Arikan сам делает бэкапы и хранит несколько последних:

| Когда | Сколько хранится |
|---|---|
| перед обновлением | 5 |
| перед переходом на PostgreSQL | 3 |
| перед восстановлением | 3 |

Ваши архивы `Arikan-*` никогда не удаляются автоматически.

:::note
Свой сайт из `/opt/mikan/data/panel/www` в бэкап не входит, храните его отдельно.
:::

## Восстановление

```bash
arikan restore /opt/mikan/backups/Arikan-20261001-031500.tar.gz
```

Перед восстановлением программа проверяет архив, останавливает контейнеры и сохраняет снимок текущего состояния. Если шаг не удался, всё возвращается как было. Свои пароль базы, образ и версия сервера сохраняются, поэтому бэкап можно перенести на свежеустановленный сервер. Бэкап панели не встанет на ноду, и наоборот.

- `-y` не задаёт вопросов.
- `--no-db-snapshot` не снимает копию текущей базы перед заменой: для PostgreSQL, которая сломана настолько, что её не выгрузить. Если восстановление не удастся, текущие данные пропадут.

Архив только с базой (как бэкап из Telegram) восстанавливает только базу: файлы сервера — `config.json`, `secrets/`, сертификаты и адаптеры — остаются как есть. Но настройки **внутри базы** приезжают из архива: адрес и порт панели, подписочный домен и пути, токен бота. Порт, который панель реально слушает, — свойство сервера (`PANEL_PORT` в `config.json`), поэтому при расхождении панель при старте исправляет настройку `panel_port` на свой порт. Ключ присоединения тоже остаётся здешний: после такого восстановления каждая нода должна присоединиться заново («Перевыпустить ключ» на странице «Ноды», затем `mikan join` на ноде). Старые бэкапы SQLite восстанавливаются и на панели с PostgreSQL. Восстановление заменяет базу целиком.

## Бэкапы в Telegram

**Telegram → Инфраструктура → Бэкапы в Telegram**: каждый день в выбранный час (по UTC) панель присылает в чат администратора зашифрованный бэкап базы. Нужно подключить чат администратора, см. [Уведомления](/arikan/operations/alerts/).

- **Пароль шифрования**: от 20 символов, кнопка «Сгенерировать». Потерянный пароль не восстановить.
- «Отправить сейчас» присылает бэкап сразу.
- В бэкапе только база: пользователи, тарифы, настройки, токен бота. файлов настроек (`config.json`, `secrets/`), сертификатов и ключей нод в нём нет, для них держите бэкапы на сервере.
- Файл не больше 50 МБ, это лимит ботов Telegram.

Восстановить на сервере (нужна утилита [age](https://github.com/FiloSottile/age)):

```bash
age -d -o Arikan.tar.gz Arikan-….tar.gz.age
arikan restore Arikan.tar.gz
```
