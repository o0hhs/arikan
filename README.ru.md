## Установка

На чистом сервере с Ubuntu 22.04+ или Debian 12+ (amd64 или arm64):

```bash
curl -fsSL https://github.com/o0hhs/arikan/releases/latest/download/install.sh | sudo bash
```

Установщик по шагам:
1. Спрашивает язык панели и, если нужно, домен. Проверяет, что домен указывает на этот сервер.
2. Ставит Docker, если его нет.
3. Подбирает сайты для маскировки REALITY рядом с сервером.
4. В конце выдаёт ссылку на админку.

Меню управления потом открывается командой `arikan`.

Нода для уже работающей панели: страница **Ноды** в панели (или `arikan node add`) выдаёт команду с ключом:

```bash
curl -fsSL https://github.com/o0hhs/arikan/releases/latest/download/install.sh | sudo bash -s -- --join КЛЮЧ
```

Без вопросов, для скриптов: `… | sudo bash -s -- --yes --lang ru --domain vpn.example.com --email you@example.com` (все флаги: `arikan install --help`).

### Переход с обычного mikan

Уже стоит панель апстрима — переезд это просто переключение образа, данные остаются как были: форк добавляет только свои новые таблицы (все пустые), ни одна существующая строка не переписывается, а недостающие миграции панель применяет сама при первом старте.

**1. Обычный mikan.** Если панель ещё не стоит, сначала штатная установка — она же ставит Docker, файрвол и compose:

```bash
curl -fsSL https://github.com/Miroshka000/mikan/releases/latest/download/install.sh | sudo bash
```

**2. Переключение на форк.** Одна команда — она берёт свежий стабильный релиз из подписанного указателя релизов форка и проверяет его подпись:

```bash
curl -fsSL https://raw.githubusercontent.com/o0hhs/arikan/main/scripts/install-fork.sh | sudo bash
```

Панель старше 0.5.0.0 (ещё на SQLite) сначала обновляется до 0.5.x штатным установщиком: этот скрипт работает с панелью на PostgreSQL.

**Нода** (сервер, где из `/opt/mikan/compose.yaml` поднята только служба `node`) переходит этой же командой: панели, postgres и pg_dump там нет, и скрипт это учитывает. Роль он видит по `MIKAN_MODE=node` в `/opt/mikan/.env`, а если строки нет — по самому compose.yaml. На ноде вместо копии базы снимается архив её собственных данных (`/opt/mikan/data/node/backup/backup-<дата>-before-fork.tar.gz`: ключи, настройки, соединения), схема и таблицы `referral_*`/`campaign_*` не проверяются (их создаёт панель на своей стороне), а обновления ведёт панель через страницу **Nodes**. Если у панели несколько адресов и нода сама не угадывает нужный, добавьте `--node-panel-address IP`.

Что делает скрипт (`scripts/install-fork.sh`):

- читает указатель релизов и манифест форка, сверяет их подпись ключом форка и берёт образ из манифеста — пином по digest (`--image ghcr.io/o0hhs/arikan:<тег>` называет другой образ: бету или свою сборку);
- сначала тянет образ: если что-то не так (пакет ещё закрыт, нет доступа в реестр) — ничего не меняется, стек как работал;
- ставит на хост команду форка и её юниты обновления **до** переключения образа и лишь затем выключает стоковый апдейтер: стоковая команда остаётся в `/usr/local/bin/mikan.stock`, файлы её юнитов — на месте. Без этого кнопка **«Обновить»** в панели и ночной таймер по-прежнему ходили бы к апстриму и однажды положили обычный mikan поверх форка;
- делает резервную копию — базы (pg_dump) на панели, данных ноды (tar) на ноде — и `.env`;
- переключает образ и перезапускает стек, назвав службу по роли (`panel` или `node`), и сначала убедившись, что такая служба в `compose.yaml` вообще есть;
- на панели сверяет схему базы, число клиентов, тарифов, платежей; на ноде — что она отвечает своей командой; в обоих случаях проверяет, что апдейтер на хосте — форка: проверка не прошла — скрипт сам откатывается;
- автообновление оставляет включённым: у форка свой адрес релизов и свой ключ подписи, панель не «вернёт себя» на апстрим. Ключ `--disable-auto-update` нужен только для старых сборок форка, у которых адрес релизов ещё указывал на апстрим.

Посмотреть, что скрипт собирается сделать, не меняя ничего: тот же запрос с `--dry-run`. Если образ не скачивается — откройте пакет: GitHub → Packages → arikan → Package settings → Change visibility → Public (скрипт сам подскажет это на неудаче).

**3. После перехода.** На странице **Платежи** включите реферальную программу («Рефералы») и создайте метки кампаний. Всё остальное — пользователи, тарифы, платежи, ноды, ссылки подписок — без изменений.

**Откат на обычный mikan** — та же команда с копией, снятой до перехода (платежи, клиенты и тарифы вернутся к состоянию на её момент; данные реферальной программы и меток кампаний в копию не входят). Вместе с ней возвращаются стоковая команда и её юниты обновления:

```bash
curl -fsSL https://raw.githubusercontent.com/o0hhs/arikan/main/scripts/install-fork.sh | sudo bash -s -- --rollback /opt/mikan/data/panel/backup-<дата>-before-fork.dump
```

На ноде копия — это архив её данных, и откат называется так же (скрипт сам смотрит на расширение: `.dump` — панель, `.tar.gz` — нода):

```bash
curl -fsSL https://raw.githubusercontent.com/o0hhs/arikan/main/scripts/install-fork.sh | sudo bash -s -- --rollback /opt/mikan/data/node/backup-<дата>-before-fork.tar.gz
```

## Чем форк отличается от официального mikan

Официальный mikan живёт в [Miroshka000/mikan](https://github.com/Miroshka000/mikan). Этот репозиторий — форк: панель апстрима со всем, что она умеет, плюс всё перечисленное ниже. За апстримом следят: его релизы переносятся сюда, поэтому исправления и новинки официальной панели здесь тоже появляются (сейчас перенесён 0.5.2.0). То, что есть в апстриме, не трогается — форк только добавляет.

### Деньги, продажи и подписчики

- **Реферальная программа** (Платежи → Рефералы): приглашения по ссылке бота, баланс пригласившего, правила вознаграждения по тарифам. Награда — отрезок в десять дней тарифа, который купил приглашённый: самый дорогой платёж первым, более дешёвый тариф никогда не понижает более дорогой, а Звёзды зарабатывают по курсу `stars_rate` программы. Подробно ниже.
- **Метки рекламных кампаний и агенты** (Платежи → Реклама): ссылка с меткой на каждую рекламу и счётчики по ней, а агент — собственный логин и пароль — зарабатывает процент, который вы назначили (1–100, запоминается на каждый платёж), с продаж закреплённых за ним кампаний. Агенты видят свою панель по собственному секретному пути; выплаты — запись: ошибка правится новой записью, удалить нельзя. Подробно ниже.
- **Коды доступа** (Платежи → Промокоды): код может открыть тариф, скрытый от витрины, — покупкой по его цене или бесплатно, как задан код.
- **Тариф под себя**: покупатель собирает план — срок, трафик, устройства, — а панель считает его цену из базовой и коэффициентов, заданных админом (Платежи → Тарифы, карточка конструктора).
- **Пакеты устройств**: дополнительные места продаются пакетами (+2, +7) с ценой по сроку; пока пакет в продаже, докупка одного устройства не предлагается и не выставляется в счёт.
- **Партнёры** (Платежи → Партнёры): задел франшизы — код входа партнёра (`/start partner_<code>`), процент комиссии и баланс с леджером; каждая оплата в рублях подписчика, пришедшего по коду, начисляет долю, а возврат её забирает.
- **Тариф можно удалить навсегда**: «Удалить навсегда» рядом с архивированием; оплаты сохраняют название тарифа, а тариф с подписками удалить не дадут и скажут причину.
- **Админ слышит о каждой оплате**: прошедший платёж сообщает админам бота в их личные чаты — а также в чат оповещений панели, если он подключён, — кто купил, что, за сколько, каким способом и на сколько.
- **Бизнес-аналитика** (Аналитика): выручка в рублях и Stars, MRR/ARR, ARPU/ARPPU/LTV, конверсия триала, отток, когорты удержания, выручка по тарифам, способам оплаты и рекламным кампаниям за 30, 90 или 365 дней.
- **Сценарии автоматизации** (Автоматизация): правила «событие → условия → действия» по всем событиям панели, с паузой на клиента, пробным запуском и журналом. Действия — сообщение админу или клиенту, продление, трафик, готовый промокод и персональная одноразовая скидка, которую сценарий создаёт и отправляет сам.
- **Вебхуки на свой сайт** (Настройки → Система): панель шлёт подписанные события на ваш адрес — `subscription.paid` с данными подписки и платежа, а также остальные события потока в общем конверте, включая `payment.failed`. Доставка с повторами и паузой, кнопка «Проверить» и история за 7 дней.

### Бот

- **Бот выпускается вместе с панелью**: свой бот-аддон форка (`arikan-telegram`) вшит в образ как встроенный источник, подписанный релизным ключом, которому панель и так доверяет; панель сама ставит его и сама отдаёт ему бота, забирая его у бота маркетплейса, где поставила его сама.
- **Цветные кнопки, премиум-эмодзи, надписи кнопок** (Telegram → Меню и тексты): каждая собственная кнопка принимает цвет Telegram (обычная, синяя, зелёная, красная), id премиум-эмодзи и свой эмодзи или надпись.
- **Бот, который понимает покупатель**: четыре кнопки в главном меню; подключение сперва отдаёт подписку приложению — импорт в один клик (`happ://`, `incy://`, `kabosu://`) главная кнопка, а установка приложений отдельный экран; весь экран подключения настраивает админ (Telegram → Меню и тексты → Экран подключения).
- **/admin в боте, с ролями**: суперадмин, поддержка (находит подписку по id/@username/номеру платежа, даёт дни, сбрасывает сессии, блокирует), техник; спящие триалы уходят одной рассылкой.
- **Промокоды вводятся в чате**; срок измеряется в месяцах; один способ продажи мест; аддон сообщества `mikan-subs-bot` работает здесь.

### Панель

- **Material 3 Expressive**: админ-панель и страница подписки (Mini App) перестроены на новом языке дизайна — цветовые роли, форма, типографика и моушн, — а в пикере тем добавилось двенадцать новых: шесть пар светлая/тёмная по алгоритму тональных палитр Google и Roboto Flex.
- **Режим производительности**: интерфейс без анимаций и размытий — мгновенный и плоский, фоновый опрос замедляется; выбор живёт в браузере.
- **Главная такая, какой её собрал админ**: у каждой карточки свой переключатель; дата пишется коротко, с временем или крупно с идущими секундами, в часовом поясе читателя.
- **Публичная страница мониторинга** (Настройки → Безопасность): свой адрес за собственным паролем (хранится только хеш), только сервис и никогда — подписчик; у каждого блока свой переключатель, чувствительные выключены, пока их не включат.
- **Куда ходят клиенты**: панель считает трафик каждой подписки по сайтам и хранит по дням; сайт блокируется из карточки клиента, а одна кнопка стирает всё собранное. Раздел живёт в Настройки → Маршрутизация, рядом с DNS.
- **Диск ноды — в панели**: что занимает каталог данных, сколько накопилось мусора и уборка в одну кнопку; старые образы релизов чистит сам установщик после каждого успешного обновления.
- **Права и подтверждения** (Настройки → Админы, Подтверждения): кастомные роли с набором прав; удаление клиента, перевыпуск ссылки, возврат и восстановление базы ждут второго админа. Подтверждённое действие захватывается статусом «выполняется», поэтому два админа не выполнят его дважды, а сбой возвращает запрос в «подтверждён» для безопасного повтора.
- **Бэкапы в S3 и восстановление из панели** (Настройки → Система): зашифрованный дамп по расписанию в S3-совместимое хранилище, срок хранения, история, ручной запуск и восстановление с предварительным свежим бэкапом и подтверждением второго админа.
- **Проверка клиента** (карточка клиента → «Проверить подключение»): срок, трафик, устройства, тариф, доступные протоколы, ноды и сама ссылка подписки — с причиной и кнопкой исправления. Проверка только читает и ничего не меняет.
- **Карточка клиента говорит больше**: «Ноды и протоколы» называют ноду у каждого протокола с использованием за последний час; карточка шириной со список пользователей, умеет сортировку и кнопку «Открыть в Telegram».
- **Подписка с нод**: выбранные ноды сами отвечают по ссылкам подписки профилями, которые панель им присылает, — ссылка работает, пока сервер панели заблокирован или лежит. Запись живёт до конца срока подписки (без срока — 30 дней), просроченная отвечает `410` понятными словами, а отозванная исчезает за минуту.

### Ноды, сеть и блокировки

- **CDN-пресеты**: VLESS · TLS · XHTTP · CDN (режим `stream-one`, адрес клиента в блоке «За прокси») и вариант **GET-аплоад** для CDN, отказывающих POST, — включая Яндекса, — который ездит на небольшой вилке ядра mihomo. `scripts/cdn-check.sh` проверяет цепочку по слоям.
- **VK TURN** (карточка ноды → ⋯ → VK TURN): там, где белый список пропускает только звонки, нода несёт выбранное подключение через TURN-серверы звонков VK, а в подписке оно появляется ещё раз — обычным сервером на адресе самого клиента.
- **Копирование протоколов** (Протоколы → протокол → Копировать): поднять тот же протокол с теми же ключами и маскировкой на другом порту или на другой ноде, поменяв только порт и, у REALITY, сайт маскировки.
- **Выключенные протоколы тарифа**: выключенный в тарифе инбаунд не входит в подписку ни одного клиента этого тарифа — и на ноды не попадает, чтобы приложение даже не пыталось, — а личные переключатели клиента не откроют закрытое.
- **Балансировка**: у авто-группы подписки появился третий режим — распределяет клиентов по серверам, закрепляя сайт за одним сервером, чтобы сессия сохраняла свой адрес выхода.
- **Нода говорит, что не так**: собственная проверка интернета (egress) и аптайм на карточке, упавшие слушатели с причиной и подсказкой про занятый порт, переходы здоровья в журнале панели, отменённые запросы пишутся тихо.
- **Аварийная нода и MTProto**: истёкшая подписка держит только серверы аварийной ноды — с ограничением скорости, чтобы Telegram оставался доступен, — а MTProto-прокси для самого Telegram задаются одной настройкой.
- **Защита от блокировок (anti-RKN)**: API ноды отвечает только своей панели (и `arikan doctor` скажет, если это не так), порт 80 отвечает 301, нода держит свою HTTPS-страницу (она же — цель маскировки REALITY), а в документации есть страница о жёсткой настройке.
- **DNS на выходе ноды** для всех клиентов — доменные правила и маршрутные пресеты (включая Gemini) работают и у приложений на Xray; выходом может быть share-ссылка; а проверка показывает по геобазе, где выход на самом деле.
- **Кто ходит через ноду**: по каждой ноде — клиенты с их трафиком и последним появлением, и наоборот по пользователю.
- **Завершение переезда панели**: после восстановления из бэкапа на новом сервере `arikan admin migrate` назначает новый адрес, сохраняет ссылки подписок и проверяет ноды — они принимают переехавшую панель без перерегистрации. Панель также сама отдаёт свой бэкап (Настройки → Система): дамп базы скачивается прямо из панели.
- **Свой канал обновлений**: образ `ghcr.io/o0hhs/arikan`, релизы на этой странице, манифест подписан ключом форка, и `arikan update` с кнопкой **Обновить** ходят сюда, а не к апстриму. Документация — [o0hhs.github.io/arikan](https://o0hhs.github.io/arikan).

## Промокоды

Администратор может создавать скидочные промокоды и коды на бонусные дни или трафик.
Подписчики активируют их в Telegram Mini App и видят историю активаций. Бонусный трафик
можно начислить в основной баланс или выбранный пул. Скидочные счета доступны только
через способы оплаты с поддержкой возврата: Telegram Stars и адаптеры, которые заявили
такую возможность. Тогда Arikan сможет вернуть оплату, если резерв промокода истёк до
подтверждения платежа провайдером.

## Реферальная программа

Подписчики приглашают других своей ссылкой (`t.me/<бот>?start=ref_<код>`). Telegram-аккаунт
навсегда закреплён за одним пригласившим, поэтому приглашённого нельзя посчитать дважды.
Что получает пригласивший, задают правила, которые администратор пишет по тарифам: процент
на внутренний баланс, бонусные дни к своей подписке или и то и другое, плюс правило с
порогом «каждая N-я оплата». Балансом можно частично оплатить счёт. Программа включается,
правила и тарифы задаются на странице **Платежи → Рефералы** в панели.

## Метки рекламных кампаний

Дайте каждой рекламе свою ссылку (`t.me/<бот>?start=camp_<метка>`) — и панель посчитает по
каждой кампании, сколько людей пришло, сколько купило и сколько продлило. Статистика на
той же странице **Платежи**, так что окупаемость кампании видно прямо в панели, а не только
в рекламной сети.

## Как это устроено

```mermaid
flowchart LR
    A[Браузер] -- HTTPS, секретная ссылка --> P[панель Arikan<br>пользователи · тарифы · подписки]
    P -- unix-сокет / TLS с пиннингом --> N1[нода Arikan<br>внутри mihomo]
    P -- TLS с пиннингом --> N2[удалённая нода]
    C[VPN-приложения] -- REALITY · QUIC · … --> N1
    C --> N2
    C -. подписка .-> P
```

Панель и нода — два процесса из одного образа. Обновление или перезапуск панели не роняет VPN. Удалённые ноды добавляются по ключу со страницы **Ноды**.

## Управление сервером

Команда `arikan` открывает меню. Команды можно вызывать и напрямую, они на английском:

| Команда | Что делает |
|---|---|
| `arikan status` | контейнеры, версии, состояние, доступное обновление |
| `arikan logs [panel\|node]` | логи в реальном времени |
| `arikan url` | ссылка на админку |
| `arikan reset-password` · `reset-path` · `disable-2fa` | вернуть доступ |
| `arikan update` | обновить сейчас: сначала бэкап, при сбое откат |
| `arikan backup` · `restore FILE` | бэкапы в `/opt/mikan/backups` |
| `arikan admin migrate --public-host IP` | завершить переезд панели после восстановления на новом сервере: новый адрес, ссылки те же, ноды проверяются |
| `arikan node …` · `arikan inbound …` | ноды и протоколы |
| `arikan targets scan` · `apply` | сайты для маскировки REALITY рядом с сервером |
| `arikan join КЛЮЧ` | на ноде: взять новый ключ из панели |
| `arikan restart` | перезапустить контейнеры |
| `arikan doctor` | проверить сервер: Docker, порты, файрвол, часы, DNS, диск |
| `arikan support КОД` | отправить диагностику в обращение поддержки, когда панель недоступна |
| `arikan support-access on\|off` | разрешить или запретить доступ для поддержки на этом сервере |
| `arikan api-lockdown [status\|off]` | на ноде: состояние правила «API ноды только с IP панели» или снять его сразу |
| `arikan uninstall` | остановить и удалить команду, данные остаются |

## Обновления

Панель раз в день проверяет новый релиз и показывает, что изменилось. Автообновление включается в настройках, обновиться сразу можно кнопкой **Обновить**.

Обновление делает программа на хосте:
1. Берёт образ из GitHub Packages.
2. Делает бэкап.
3. Обновляет базу и перезапускает панель.
4. Если новая версия не поднялась, откатывается.

Манифест каждого релиза подписан.

На 0.4.4 и более ранних версиях сначала обновитесь до 0.4.5, тогда переход на 0.5 с PostgreSQL тоже пройдёт кнопкой. Пропустили 0.4.5 — подойдёт команда из «Установки», она обновит существующий сервер.
